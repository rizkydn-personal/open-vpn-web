# Audit 001: existing public pages

Mode: AFTER. The repository's `antislop.md` and the five referenced antislop skills are not present in the workspace, so this audit records only the rule identifiers and requirements explicitly supplied in `task.md`.

## Findings

1. **HIGH · R-27:** An API error can make the service catalog disappear, and the public pages do not consistently distinguish empty, loading, stale, and failed data. Add explicit states and preserve age information for cached data.
2. **HIGH · R-27 / R-36:** The homepage reports the status panel as offline when metadata is stale but can still label per-service rows as active or available. Qualify stale values with their update time and avoid presenting stale values as current.
3. **HIGH · R-27:** Quota countdown renders `--:--:--` on first paint even though the server already has the reset timestamp. Render the initial countdown from a server-provided time reference.
4. **MEDIUM · R-03:** Homepage status, account counts, and quota use repeated card grids. Recompose them into compact status rows, service rows, and a quota strip for the phone-first primary task.
5. **MEDIUM · R-16 / R-36:** The hero headline is generic and the privacy statement should be precise about session storage behavior. Use text grounded in the actual create-account flow and storage lifetime.
6. **MEDIUM · R-24 / R-26:** The current mobile menu presents unavailable services as disabled text rather than a destination; ensure every service has a useful destination and explain unavailability on its page.
7. **MEDIUM · R-27:** The segment not-found, route error, and root error views use framework defaults; add consistent custom views with useful recovery links and retry behavior.

## Follow-up

Findings 1–7 are tracked in Fases 2, 5, and 7. The mobile service-menu behavior is retained only if its items remain understandable and all available services have working routes. Findings are closed only after relevant tests and browser checks pass.
